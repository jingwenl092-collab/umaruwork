### NHK 实时抓取可行性实测（重要结论）

| 能力 | 结论 | 证据 |
|---|---|---|
| NHK 官方 RSS 列表 | ✅ 可用，量大 | cat0=7 条、cat1(社会)=133 条、cat2(科学文化)=24 条、cat5(国際)=98 条 |
| RSS 入口 | `https://www.nhk.or.jp/rss/news/cat{N}.xml` → 301 → `news.web.nhk/n-data/conf/na/rss/cat{N}.xml` | |
| 每篇可得内容 | 标题 ~29 字 + 导语 ~64 字 ≈ **100 字真日文** | |
| **完整正文** | ❌ 拿不到 | 服务端 405KB HTML 里最长真实句仅 64 字；`_next/data` 404、`/api/news` 404、`*.json` 401；JSON-LD 的 articleBody 为空 |
| NHK Easy（自带 ruby） | ❌ 不可达 | www3.nhk.or.jp / www.nhk.or.jp/news/easy 全部 HTTP 000 |
| 浏览器直连 NHK | ❌ | 无 Access-Control-Allow-Origin → **必须服务端代理** |
| 其他源 | ❌ 均不可用 | Yahoo RSS 仅 46 字摘要；時事通信 / 朝日 / ja.wikinews 均 HTTP 000 |
| **振假名生成** | ✅ **SudachiPy 0.7.0 + SudachiDict_core 装成功** | `Dictionary.tokenizer()` 用（旧的 `.create()` 已废弃），`m.reading_form()` 给片假名读音 |

注意：`fugashi + unidic-lite` **装不上**（unidic-lite 构建失败），改用 SudachiPy。

### 架构影响
要做 NHK 实时抓取，项目必须从「纯静态站」改为**带 `/api` 转发的 Python 服务**
（发布时 language 从 static 改 python）。域名不变，云端 AI 讲评的 Origin 校验不受影响。

## 偶像对话模块（已完成，待发布）

- 新建 `js/data-talk.js`：4 个场景 × 3 难度 × 2 开头 + 每场景 5 句常用说法
  - 场景：`handshake` 握手会 / `hightouch` 击掌会 / `birthday` 生誕祭 / `release` リリースイベント
  - 每个场景含 `briefing`（现场什么样）、`etiquette`（礼貌与节奏）、`persona`（日文人设）、
    `openers`（按难度分组的开场白）、`phrases`（可直接用的说法，带注音+中文）
  - **角色为虚构通用成员**：check-data 用 `BANNED` 正则拦截真实团体/人名（AKB48G/指原/=LOVE 等）
- `data.js` 归一化出 `TALK`（openers/phrases 均为 `{ja,furi,zh}`）
- `app.js` 对话逻辑：
  - 开场白取自素材（即时呈现，不等 AI），之后每轮调云端 LLM
  - 单次调用同时拿 `{reply, zh, verdict, highlights, suggestions, next}` ——
    台词 + 中文翻译 + 上一句点评 + 下一句提示，一次往返，延迟可控
  - `TALK.token` 会话令牌：结束/重开后丢弃迟到回复（同 `aiToken` 思路）
  - 失败只显示错误 + 重试，不破坏已完成的轮次
  - 会话离开页面再回来可继续（`goTalk` 有会话就回聊天面板）
  - 结束时存 `localStorage['riyi_talk_v1']`（最多 30 场），设置页可展开回看
- 难度只影响 AI 说话方式：L1 短句全注音 / L2 自然口语常用汉字注音 / L3 不注音、可用省略口语
- L3 气泡按纯文本渲染（`esc(ja)`），L1/L2 用 `furiToHtml`
