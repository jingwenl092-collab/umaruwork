## TTS 实战排查：用户「朗读全都没声音」

根因不是代码，是设备侧：**系统里根本没有 ja-JP 语音引擎**。
- 查法：`HKLM:\SOFTWARE\Microsoft\Speech_OneCore\Voices\Tokens` 只有 zhCN(Huihui/Kangkang/Yaoyao)，
  `C:\Windows\Speech_OneCore\Engines\TTS` 只有 en-US、zh-CN 两个目录
- **语言包 ≠ 语音包**：Win11 在「日语 → 选项」里，语音是独立的「语音识别」+「文本转语音」两行，
  用户在设置页只装了语言包，TTS 那行没装
- 用户点设置页下载后：387MB 下完（CBS.log `DownloadProgress 100%`），但 **CBS 一直没执行安装**
  （日志停在 `WULib Mode Complete`，`Packages` 注册表里始终查不到 TextToSpeech-ja-jp）
- 因此后续让用户在**管理员终端**直接跑
  `DISM /Online /Add-Capability /CapabilityName:Language.TextToSpeech~~~ja-JP~0.0.1.0`
  （注意 `Language.Speech~~~` 是语音识别，`Language.TextToSpeech~~~` 才是朗读，别搞混）
- 装完必须**彻底退出浏览器**再打开：浏览器只在启动时扫描语音列表

### 「以前没装语音包也有声音」的真相（重要）

用户反馈旧版本不装语音包也能朗读。查 git 历史确认：109b03c / 139cbb4 的 doSpeak 都有
`if (speechVoices.length && !v) { 提示; return; }`，即**行为一直没变**，不是我们改坏了。
真正原因：浏览器自带**网络语音**（Chrome「Google 日本語」、Edge「Microsoft Ayumi/Ichiro
Online (Natural)」），`localService === false`，不需要 Windows 语音包但要联网；
它会随浏览器版本/网络/隐私设置变化而消失，所以用户「突然没声音」。

据此做的兜底（提交 `cbb326f`）：
- pickVoice 优先级改为 **本地精确 > 网络精确 > 本地同语种 > 网络同语种**，
  不再把网络语音排除掉（上一版只找 localService!==false 会堵死这条路）
- 完全找不到对应语种语音时**不再 return 静音**：不指定 voice 交给浏览器默认语音出声，
  并提示「发音可能不准 + 如何装语音包」
- 提示分三种：缺语音包 / 网络语音失败（需联网、可能被代理拦）/ 引擎卡住通用排查
- 朗读自检输出标注每个语音是「本地」还是「网络语音（需联网）」

## 用户反馈「朗读全都没声音」→ TTS 加固（v5.1）

- 先验证链路：用 mock speechSynthesis 跑 `.workbuddy/tmp-tts-smoke.js`，
  speak() 调用正常（练习页 zh-CN、阅读/对话 ja-JP，voice 也选对了）→ **不是代码接线问题，
  是设备/浏览器侧静默失败**（Chrome 的老毛病：speak() 既不发声也不报错）
- 加固项：
  1. **看门狗**：`doSpeak` 盯 `onstart`，1.2 秒没发声立刻 `showSpeechHint` 提示，
     并用 `retry=true` 再试一次（这次不指定 `voice`，交给浏览器挑默认语音）
  2. 选语音优先 `localService !== false` 的本地语音（远端/网络语音离线时最易静默失败）
  3. `speak()` 里 cancel 后等待 260ms（原 180ms）再发声——Chrome 会吞掉 cancel 后紧跟的 speak
  4. `speak()` 之后再补一次 `resume()`（Chrome 队列不启动的已知问题）；`u.volume = 1`
  5. 新增**朗读自检**按钮（`ttsCheckBtn` 首页 / `readTtsBtn` 阅读页工具栏，共用 `ttsSelfCheck(targetId)`）：
     报告可用语音数、日/中语音名，并试听「こんにちは」，2 秒内没 onstart 就给出排查清单
- 教训：TTS 的静默失败**只能靠自己盯 onstart 兜底**，`onerror` 抓不到；
  排查这类问题先用 mock 引擎确认「代码有没有调 speak」，再判断是不是设备问题
